カリンバ記譜法 v1 — モックレンダリング 3 案

S7 決定支援 (2026-07-05) · 代表フレーズ: きらきら星 冒頭 2 小節 (4/4、C 調、17-key)

判定のしかた — 各案を「この楽譜だけを見て、録音を聴かずに弾き戻せるか」で見てください。 音の高さ (どの tine か) とリズム (どれだけ伸ばすか・休むか) の両方が読み取れることが合格ラインです。 フレーズはどの案も同一: ドドソソララソー / ファファミミレレドー
案 A

数字譜 + リズム拡張

コミュニティ主流の数字タブに、音価 (ダッシュ = 前の音を 1 拍延長) と休符 (0) の規約を明示的に足した形。現行 labelNumber 出力の直接拡張。

1155665–|4433221–|

読み方: 数字 = 移動ド (1=ド)。上の点 = 1 オクターブ上。– = 前の音を 1 拍のばす。0 = 1 拍休み。1 文字 = 1 拍 (8 分音符は下線で 2 個組)。

判定ポイント — 数字がそのまま tine 刻印と一致 (17-key)。リズムはダッシュ規約を覚える必要がある。和音・グリッサンドは括弧で併記する拡張が別途必要。
案 A′

拍グリッド (手書き規約準拠)

作者の手書き譜規約 (#202 一次情報) をレンダリング化した案。紙面を基本音長の等間隔グリッドにし、伸ばし・休符は空白カラム、小節線で拍を集計。基本より短い音は例外としてカラム内にラップして詰める。横方向の距離が時間に比例する。

読み方: 1 カラム = 基本音長 1 個。文字が無いカラム = 前の音をのばす (または休み)。縦線 = 小節線。詰め文字 = 基本の半分の長さ×2。

判定ポイント — 記号の読解規則が不要 (空白と距離がそのままリズム)。小節線と空白は相互依存 (小節線が無いと空白を数えられない)。実装は現行イベント列表示からの転換になるが、beat 量子化は実装済みなので土台はある。伸ばしと休符の区別が空白だけでは付かない点は要議論 (前の音が鳴り続けているか止まっているか)。
案 B

縦型タブ (KTabS 風)

tine の物理配置を模した格子。列 = tine (楽器を正面から見た並び)、下から上へ時間が進む。行間隔 = 音価。

読み方: 下から上に読む。● がある列の tine を弾く。●から伸びる縦線 = のばす長さ。破線 = 小節の区切り。

判定ポイント — どの tine を弾くかは迷いようがない (楽器と同じ並び)。左右の手の交互も見える。一方、紙面が縦に長く、フレーズの反復構造は読み取りにくい。tuning (17/21/34-key) ごとに紙面の幅が変わる。
案 C

ハイブリッド (五線 + 数字併記)

市販カリンバ楽譜集の主流形式。リズム・休符は五線から、どの tine かは数字から読む。

判定ポイント — リズム・休符の表現力は最強で読者層も選ばないが、レンダリング実装 (五線 + 数字の 2 層同期) と修正 UI との接続コストは 3 案で最大。五線が読めなくても数字 + 音符の玉の間隔でおおよそ弾ける。
