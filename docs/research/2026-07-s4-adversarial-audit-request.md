## 重点監査項目 (チェックリスト)

1. **「同一 agent・同日」の収束リスク**: probe 追試 / partial table / ROC / 設計文書 / 判定資料はすべて 2026-07-05 に Fable が作成した。第 2 期の敵対的レビューが指摘した「3 方向収束は同一 agent の解釈」と同じ構造が再演されていないか。特に「全ての発見が per-tine tracker を支持する方向に解釈されている」点は、真に証拠が収束しているのか、解釈がバイアスされているのか
2. **fresh 減算 (ring-out 減算) の妥当性**: S0 の partial 解釈を「M3 残響ゴースト」と訂正した根拠は fresh=0.000。しかし (a) GT timeSec が遅い場合 pre 窓に attack が混入し fresh を系統的に過小評価する、(b) 減算は magnitude スペクトルの単純差で位相を無視している。**本物の ×1.26-1.47 partial を誤って殺した可能性**を検討せよ (梁理論の第 1 overtone との整合も再確認)
3. **ROC の FN 解釈**: 「FN 主因 = integer 倍音 guard のオクターブ抑圧」は guard を外した対照実験で裏取りされていない (トレイル読解のみ)。代替説明 (単純に信号が弱い等) を排除できているか
4. **FN 回収率 67%/50% の計算条件**: tolerance ±80ms・note 一致のみの greedy マッチであり、precision 0.24-0.29 の大量 FP の中から偶然一致した可能性 (偶然一致率の期待値) を評価せよ。この数字が判定資料の中核に置かれるべき強度か
5. **kill 条件の数値の甘辛**: K2 0.875 / K3 +0.015 / K4 +15% / K6 3 スプリントは、spike 実測から誘導されたものだが、「tracker に有利に読める」設定になっていないか。特に K3 の +0.015 は最低獲物 (+0.017) を下回る閾値で、獲物 1 件だけで通過できてしまわないか
6. **G2 (用途検証) の独立性**: 判定様式は S2 前に事前定義されたか (事後解釈の混入がないか)。n=1 の dogfooding で「精度が律速」を確定扱いしてよいか
7. **counter-evidence の強度**: 判定資料の反対材料 6 項は「反対のふりをした弱い藁人形」になっていないか。追加すべき反対材料があれば挙げよ
8. **NO-GO 分岐の過小評価**: 較正系 #172-174 前倒しの期待値が判定資料で公正に扱われているか

## 再監査 (検収パス) の依頼文 — 初回所見への対応後に使用

> あなたは先の敵対的監査 (2026-07-05、#203 コメント) の監査役です。監査対象 agent が対応を実施しました (対応サマリ: #203 の「監査への対応完了」コメント、実装 commit: 5f0b05b 以降)。今回の依頼は**検収**です: 各指摘について、対応が指摘の意図を満たしたか (満たした / 部分的 / 満たしていない / 対応せず・理由妥当 / 対応せず・理由不当) を判定してください。フル再監査は不要で、対応差分に絞って構いません。特に重点確認してほしいのは:
> (1) guard mode 対照実験の設計と解釈は妥当か — 「dominance 主因への訂正」「生 recall 0.97 / P 0.16」は対照から正しく導かれているか
> (2) S4 基準値の追記 (kill criteria doc) は K2/K3/K4 の判定を実際に一意にするか、残る曖昧さはないか
> (3) FN overlap artifact の chance baseline (解析的一様配置近似) は null として妥当か
> (4) timing perturbation の安定性検証は「fresh 減算が本物の partial を殺した」懸念を退けるのに十分か
