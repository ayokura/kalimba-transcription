## 監査役への依頼文 (ここから貼る)

あなたはカリンバ自由演奏の自動採譜プロジェクトの**敵対的監査役**です。次期中期計画 (第 4 期、4 方向 × 8 スプリント) の draft を、承認前に批判的に監査してください。あなたの役目は計画を褒めることではなく、**構造的な欠陥・バイアス・非現実性を見つけること**です。反証が見つからない項目は「監査した上で異議なし」と明示してください。

### 背景 (最小限)

- プロジェクト: カリンバ (親指ピアノ) 自由演奏の音声→楽譜変換。Expected Performance (事前の楽譜知識) なしで動く認識器が最終目標
- 現在地: 第 3 期 (2026-07-05〜06) が完了。per-tine 位相追跡 research line が事前固定 kill 条件 3 巡 PASS で本線投入 (PR #210)。headline は「非飽和録音限定 micro F1 + bootstrap CI95」のみ (全録音 pooled は飽和希釈のため禁止語彙): 現在 **n=11 で F1 0.744 CI95 [0.627, 0.846]**
- 実行体制の変更: 計画の著者 (Fable) は 2026-07-07 でサブスク終了。第 4 期は Opus 4.8 (主担当) + Sonnet (定型実装) + Codex (敵対的レビュー) で実行され、Fable は復帰時に合流する
- 読むべき一次資料 (優先順): sprint-plan-2026-07d.md (監査対象) → sprint-plan-2026-07c.md (第 3 期計画、構造の前例) → docs/decision-log.md 直近 3 エントリ → #203 の 2026-07-06 コメント列 (S6-S7 の実測記録) → docs/free-performance-readiness.md 冒頭注記

### 監査の重点項目 (著者の自己申告弱点を含む — 各項目に verdict を付けること)

1. **単独著者バイアス**: 本計画は第 3 期計画と異なり、敵対的レビューや発散提案の入力なしに単一モデル・単日で書かれた。方向性 A-D の選択肢空間に**漏れている第 5 の方向**はないか (例: データ収集・コーパス拡大を正面にした計画、評価計器そのものの計画、リファクタ/負債返済の計画)
2. **成功者バイアス**: 著者は per-tine line を成功させた当人。計画 A (partial table・tuning offset = per-tine の延長部品) と計画 D (#208 統合 front-end = per-tine の発展形) が**成果の自己複製**として過大配置されていないか。per-tine と独立な改善軸 (segments.py の onset 検出そのもの、和音分解、時間構造モデル等) が不当に軽視されていないか
3. **規模の現実性**: 4 計画 × 8 スプリント = 32 スプリント分は、後半 (S5-S8) の確度が C/D 濃度で埋まっている。これは「計画」ではなく「wish list」ではないか。各計画の実質的な計画価値は前半 4 スプリントのみと評価すべきか
4. **実行順序 B→A→D→C の根拠妥当性**: B 先行の根拠は「認識器不触で新体制の立ち上げリスク最小」だが、第 3 期 dogfooding の暫定結論は G2「**精度が律速**」だった。精度律速なら A/D 先行が筋では? 「B は G2 の反証実験を兼ねる」という著者の理屈は後付けの正当化ではないか
5. **数値前提の検証**: 計画中の数値 (headline 0.744 CI95 [0.627, 0.846] / ΔR +0.020 / 1955b5bd 0.509 / correction cost 0.451 / FN ~170) を一次資料 (#203、benchmark_baseline.json) と突き合わせ、誤記・都合の良い丸めがないか
6. **新体制への引き継ぎ耐性**: この計画は「Fable の置き土産」。Opus 4.8 が S1 冒頭の受入チェックで自力実行できる粒度か。暗黙知 (著者だけが知る文脈) に依存した記述はないか — 具体例を挙げること
7. **Fable 復帰待ち構造の硬直リスク**: 「中間ゲートで凍結して Fable を待つ」選択肢が、新体制の判断回避 (難しい判断を先送りする誘因) にならないか。ガードレール設計で防げているか
8. **ガードレール 15-17 の穴**: 新設 3 本 (計画レベル硬ゲート / agent 主導 GT 裁定の運用化 / 飽和卒業ゲート手続き) に悪用・形骸化の余地はないか。特に 16 (agent 裁定 GT) は「認識器の弱点を agent 裁定 GT が継承する」自己参照リスクの手当てが十分か

### 出力形式

- 項目 1-8 それぞれに: **verdict (問題あり/軽微/異議なし)** + 根拠 (一次資料の参照付き) + 問題ありの場合は具体的な修正提案
- 最後に総合判定: 「このまま GO 可 / 修正後 GO / 再設計」の 3 択 + 修正必須項目のリスト
- 計画を代筆しないこと。指摘と修正提案まで (反映は著者側で行い、変更は decision-log に記録される)
